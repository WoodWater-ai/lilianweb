### 执行分工（用户最新确认）

本任务只修改官网前端页面、前端交互、展示素材与交接文档，不实施账号服务、组织配置、模板配置、供应商接入、数据库或部署改造。前端可展示注册与试用状态并预留接口边界；未接通时明确提示，不把演示当成真实登录、额度或生成。

## PPT 参考补充：完整产品价值与页面结构

依据用户补充的两页 PPT，本次规划必须同时讲清“体验操作简单”和“完整产品覆盖商品内容生产流程”。以下为方案补充，尚未执行整体页面改版。

### 定位与首屏

礼链官网继续面向全品类电商，AIGC 产品页以有真实案例的服装场景切入。PPT 的“服装电商视觉生产工作台”用于场景说明，不把整个礼链品牌改成仅服务服装。

AIGC 首屏主张建议：**商品一上新，图片视频一起出。**

说明建议：面向持续上新的品牌与电商团队，以商品和 SKU 为起点，连接图片、视频生产与素材管理。

注明适合：品牌负责人、电商负责人、内容生产负责人。配图采用白底图、模特场景图、细节图及原视频/复刻结果组成的同组素材展示；视频案例是已有结果，不暗示免费试用实时生成视频。

首屏统一主按钮：“立即体验”，引导同一个轻量体验区；预约演示转为体验后和商务咨询入口。免费体验真实接通前，不对公开访客显示可兑现的注册赠送承诺。

### 三项价值主张

| PPT 提炼 | 官网表达 | 对应证据 |
|---|---|---|
| 审美沉淀为模板 | 把选好的视觉风格变成可复用模板，减少重复配置 | 固定模板案例、不同输出类型；不公开模板提示词 |
| 同一商品连续生产图与视频 | 围绕同一商品准备场景、细节及视频表达 | 已确认的亮绿色家居服案例，原片与复刻结果 |
| 生成后能继续管理 | 任务、审核、素材归档衔接，适配团队持续上新 | 商品管理与素材管理局部界面，明确 ERP 对接边界 |

不补写未经验证的提效倍数、成本下降比例、转化率或“完全保持商品一致”等承诺。

### 四大能力必须保留

| 能力 | 营销展示重点 | 免费试用范围 |
|---|---|---|
| 商品管理 | 商品与 SKU、商品信息、素材关联；ERP 接入按实际项目说明 | 不开放商品库、ERP、批量导入 |
| 图片素材生产 | 主图、场景、细节、上身与多角度等成果；九宫格独立示例 | 一张白底图，使用模板广场指定模板输出一组场景图 |
| 视频素材生产 | 首帧视频及授权参考视频复刻，展示镜头与节奏的实际案例 | 仅预设素材模拟操作，播放已有结果 |
| AI 自由创作 | 图片/视频引用、多轮创作与结果管理的价值；功能交付状态在实施时核验 | 不开放对话创作、提示词优化或结果转任务 |

四块采用“能力标题 + 一句业务价值 + 效果图/局部界面”的展示方式。移动端顺序排列；不把 PPT 整页缩成图片，避免小字不可读。视觉沿用官网深绿与暖白，不照搬 PPT 橙色，也不新增“达芬奇密码”作为官网主品牌。

### 补充商品生产流程

页面增加简洁流程：**商品与 SKU → 图片生产 → 视频延展 → 审核与素材归档**。

ERP 同步/回写作为“按需对接”的分支说明。PPT 出现“实时同步”和“ERP 回写”，但它们不能直接推导为支持所有 ERP、无需配置或默认标品已含。上线前核实支持的系统、方向（读取/回写）、触发方式和交付方式，再写具体承诺。

### AIGC 页最终模块顺序（本节为最新布局依据）

1. 产品首屏：上新价值、目标人群、同组图视频成果、立即体验统一入口。
2. 三项价值：模板复用、商品图视频衔接、结果管理。
3. 真实图片案例：白底图 → 场景图 + 细节图。
4. 更多商品表达：用户九宫格作为独立效果案例，不暗示一次免费试用生成九张。
5. 视频能力：第一组原视频与复刻结果内嵌播放，说明首帧与复刻两种用途。
6. 四大能力：商品管理、图片生产、视频生产、AI 自由创作。
7. 生产流程：商品/SKU 到审核归档，ERP 按需对接。
8. 使用方式：标准产品、按需定制；简要区分免费试用与完整工作台，附 FAQ 和预约入口。

首页仅提炼主张、代表案例和试用入口，不复制全部长内容。电商解决方案页继续承接履约及定制服务，城市合伙人页继续承接渠道申请。

### 新增验收点

- 访客能分清免费体验只是固定模板图片试用，完整产品还包括商品、视频、自由创作和素材管理。
- 四大能力、三项价值和生产流程均有对应位置；截图仅说明能力，不暴露完整配置操作。
- 同一 SKU 案例与独立九宫格不混淆，现有视频展示与实时图片试用不混淆。
- ERP 实时同步/回写、多轮创作等具体宣传语有交付核验依据，未核验的表述保持待确认或按需对接。

## 用户明确需求

- 手机号输入，接入短信验证完成注册。
- 企业查询并选择企业，企业字段选填。
- 注册赠送 3 次体验机会。
- 图片试用只开放一张白底图输入，使用礼链指定的一套模板，用户查看生成效果。
- 视频提供首帧 + 复刻的模拟操作，以 mock 数据展示。
- 试用操作区只保留必备能力；其他营销区域继续展示产品能力。减少完整操作细节外露，不削弱产品效果展示。

## 业务规则（注册与组织流程已确认，其余建议按下文标注）

1. 手机号验证码登录与注册合并，首次验证成功发放 3 次图片体验，同一手机号再次登录不重复赠送。企业信息可跳过，查询失败不阻断注册；选中企业不代表已认证该企业身份。
2. 每次提交一张白底商品图，使用后台指定的模板广场模板，返回一组场景图；不再承诺“场景图 + 细节图”固定两张组合。结果数量及组图规格由所选模板决定，前端按返回的图片列表展示。一次组图体验计一次，额度扣减时点、部分失败/重试补偿由全栈工程师按现有任务体系实现并明确交付规则，不在前端计费。
3. 视频模拟不扣这 3 次额度，入口和结果明确标注“示例演示，非本次实时生成”。使用配套的预设首帧、参考片和结果片；用户可模拟选择首帧和点击复刻。不能将任意用户上传图配上无关视频，假装是生成结果。
4. 首版可上传、预览白底图；统一模板及生成参数由服务端配置。由业务方与全栈工程师从现有模板广场选定一套效果较好的场景组图模板，并核实适用品类；前端不开放模板选择或参数编辑。
5. 图片成功后提供结果预览、再次体验和联系礼链；额度用完仍可看已有结果。是否开放原图下载、结果保留时长和体验额度有效期留待业务确认；不先引入支付、积分商城或复杂账号中心。
6. 企业查询在已验证手机号后按关键词触发，去抖并限制频率，只取企业名称与必要企业标识。查询无结果或上游不可用可跳过，不展示无关工商资料。

## 最小页面流程

官网“免费体验” → 手机号 + 验证码 → 企业选择（选填，可跳过） → 图片体验。

图片体验页只保留：

- 顶部：礼链、图片体验 / 视频演示、剩余次数。
- 输入：一张白底商品图（上传、预览、替换）。
- 主按钮：生成效果；显示实际处理中状态。
- 输出：一组场景图，按实际返回数量展示及再次体验 / 联系礼链。

视频演示仅保留：预设首帧选择 → 固定参考片 → 模拟复刻 → 预设结果播放。加载反馈必须表达为演示过程，不伪装真实推理进度。

删除公开试用页中的提示词、负面词、模型/供应商、分辨率/比例参数、模板选择器、参考图库、上下装合成、资源中心、任务队列及批量操作。沿用官网现有深绿、暖白视觉；不移植完整版工作台的三栏框架。

## 防止完整交互外露

营销区保留商品素材管理、图片生产、视频生产等能力模块，使用效果图、多场景九宫格及必要的局部界面示意体现能力。现有完整工作台截图逐张评估：可展示模块概貌；暴露完整配置、提示词或参数的画面改用局部示意。不再采用“一律收起所有产品能力区域”的方案。公开试用页不提供完整版操作控件。

提示词和内部配置不能进入 HTML、JavaScript、网络响应或公开 source map。浏览器只提交上传资源标识及幂等请求标识；由后端决定固定模板与模型配置，拒绝客户端额外配置字段。面向公网的接口不直接暴露后台权限，也不能给试用账号后台管理权限。

隐藏 UI 只能减少展示细节，不能阻止竞争者注册和查看公开结果。发布包仅包含评审通过的展示素材；不再使用的敏感界面截图不随新版发布。本地删除或生产清理需另行授权。

## 外部接入契约（全栈工程师负责，尚未实现）

- 短信：发送验证码、验证一次性验证码；限制手机/IP发送频率及校验次数，设置验证码有效期，日志不记录验证码或密钥。供应商失败不显示发送成功。
- 企业查询：输入关键词，返回必要企业名称/标识；可跳过、可超时降级。
- 图片：服务端校验文件类型、真实图片内容、体积/像素边界，私有对象存储与用户归属校验；服务端提交固定模板任务，查询或接收可信完成回调，返回用户自己的结果。
- 会话：服务端会话与 HttpOnly Cookie、同源请求校验；退出或会话失效后重新验证手机号。
- 额度：注册赠送一次、原子预占、幂等提交、成功结算、失败释放；回调验签、重复回调去重，不能相信浏览器“生成成功”。
